# WP5 Audit: Industrial And Systems OPD Claims

Date: 2026-05-13

Scope: industrial/model-report OPD claims, speculative/draft-model OPD, multi-teacher routing, cross-tokenizer/logit-serving support, and framework readiness.

Source rule: primary or official sources only. Exact snippets are kept short; `not found` means I did not find public primary-source evidence satisfying that criterion.

Strict OPD criteria:

- C1: current student/policy/draft model generates the rollout, sequence, prefix, token, or action state used for training.
- C2: a teacher, target model, privileged model, domain teacher, or multi-teacher router supervises that exact student-generated state.
- C3: the objective consumes that supervision as distillation-style signal beyond scalar reward.

## Concise Memo

The strongest WP5 strict rows are stage-scoped, not whole-pipeline labels. Qwen3 has a strict on-policy distillation stage for lightweight models, but the Qwen3 pipeline also contains cold-start SFT, RL, mode fusion, and general RL. Nemotron-Cascade2 has a strict MOPD stage inside Cascade RL: it samples student responses, routes each example to a domain teacher, and uses sampled-token log-prob differences as dense token-level distillation advantage. MiMo-V2-Flash similarly documents MOPD as a post-training stage with domain-specialized teachers and sampled-token reverse-KL/log-ratio advantages. DistillSpec is strict for the draft-generated data variant: the draft/student generates data and the target model supplies white-box distributions through an f-divergence objective.

The main downgraded industrial claims are Gemma 2 and Gemma 3. Gemma 2 clearly discloses pretraining KD and a terse post-training statement about distillation on the student's distribution, but the public report does not expose enough rollout/objective detail to certify strict current-policy OPD. Gemma 3 discloses sampled-logit KD and IT distillation from a large teacher, but no current-student rollout loop in the public report. DeepSeek-R1 distilled checkpoints are a clean false positive: they are SFT-style fine-tunes on an 800K supervised data mixture, not OPD.

The systems theme is teacher-forward cost. Public mechanisms include sampled-token log-probs instead of full-vocabulary distributions in Nemotron/MiMo, prefix scoring in Fast OPD, cached teacher log-probs in Lightning OPD, draft-generated data in DistillSpec, teacher-acceptance filtering in Speculative KD, vLLM/SGLang/Megatron/Ray serving backends, sequence packing, FP8, and batching. Cached log-probs and offline rollouts are valuable systems techniques but usually fail strict current-policy freshness.

Framework support is uneven. TRL `GKDTrainer` can implement strict text OPD out of the box when `lmbda=1.0` and a teacher model is supplied. NeMo RL now has an official on-policy distillation example and supports distributed rollout/training backends; its README still lists multi-teacher and cross-tokenizer distillation as roadmap/improved support rather than fully audited public examples. verl and OpenRLHF are strong RL/RLVR infrastructure, but their official README evidence is reward/RL-oriented unless a downstream recipe adds teacher-logit dataflow.
