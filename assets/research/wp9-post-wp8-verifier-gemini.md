# WP9 Post-WP8 Verifier Pass (Gemini)

## Concise Memo

Scope was limited to rows already present after the WP6/WP7/WP8 merges. I did not discover new papers and did not evaluate benchmark quality. I audited only whether the assigned `strict_opd` and `borderline_strict` claims still satisfy the repository C1/C2/C3 definition, using primary-source URLs already tracked by the repo: arXiv/OpenReview/official reports, plus official project/GitHub docs where industrial reports are terse.

Result: the frontier rows mostly survive, but only with stage/component scoping preserved. Clean strict rows remain strict where the same current student rollout receives token/action/coordinate teacher supervision consumed by KL/log-prob-style objectives. Borderline rows remain below strict for stable reasons: mixed rollout provenance, hard-label expert continuation, response-level discriminator feedback, quality gating, PPO/GRPO advantage shaping, or diffusion/flow field objectives. The only conservative verifier concern is the public Qwen3 OPD stage: it should remain stage-scoped and `needs_review`/medium confidence unless the table accepts the terse technical-report wording as sufficient for C1/C2/C3.
